# LIMS 去标识出数 API（支持源文件换版）

单实例 FastAPI + SQLite 服务：读取 LIMS 检验明细 CSV 与初始同意名单，异步生成去标识批次 CSV 供统计员下载。**受试者号被替换为跨批次稳定的随机研究代号，其余所有值与行序保持不变。**

本版新增**源文件版本管理**：队列研究数据员收到 LIMS 的整份更正明细后，可上传原格式 CSV 换版；后续出数改用新版，已有批次仍可追查其来源版本。换版不影响同意、研究代号与旧批文件。

## 快速开始

```bash
docker compose up --build
```

- Swagger UI: <http://localhost:8000/docs>
- OpenAPI JSON: <http://localhost:8000/openapi.json>
- 健康检查: <http://localhost:8000/healthz>

数据卷 `deid-data` 挂载到容器 `/data`，保存 SQLite 库（同意状态、代号注册表、源版本登记、批次登记）、**源文件各版本（`/data/sources/v<N>.csv`）**、批次清单与生成的 CSV。镜像以非 root 用户运行。

### 端到端演示（换版 × 生成交错 + 撤回生命周期）

```bash
docker compose up --build -d
python3 scripts/demo.py            # 默认 http://localhost:8000
```

脚本分两部分。**A 部分（源换版）**：

1. 查询当前源版本——配置 CSV 在首次启动时登记为**初版 v1**；
2. 发起批次后，在其**生成期间上传第一份更正** → 该批次始终固定在 v1（不混用新数据），换版后的新批次固定 v2；批次详情与列表都注明 `source_version`；
3. 仍以旧版 v1 为依据的上传返回 **409 冲突**；改以 v2 为依据后第二份更正激活为 v3；
4. 每个历史源版本都可按摘要校验后下载，用于批次溯源。

**B 部分（撤回，规则照旧）**：生成中撤回 → 批次 `invalidated`、下载 410；重新同意不恢复旧批；新批次正常；再次撤回连已完成批次一并失效。

`docker-compose.yml` 设置 `ROW_DELAY_SECONDS=0.02` 模拟逐行处理耗时，使“换版/撤回发生在生成期间”可稳定复现；生产环境可去掉该变量（默认 0）。

## 样例数据

| 文件 | 内容 |
| --- | --- |
| `samples/inputs/lims.csv` | 初始检验明细：`subject_id,test_date,test_item,value`，10 名受试者 × 3 次检验 × 5 个项目，共 150 行（首次启动登记为 v1） |
| `samples/inputs/lims_correction_1.csv` | 更正样例一（整份）：更正 S001、S003 的测量值（如 S001 的 CBC-WBC 8.0→9.0），格式与行数不变，上传后成为 v2 |
| `samples/inputs/lims_correction_2.csv` | 更正样例二（整份，基于样例一）：更正 S007（9.0→11.0）并新增受试者 S011 的 5 行，共 155 行，上传后成为 v3 |
| `samples/inputs/initial_consent.csv` | 初始同意名单：`S001`–`S008`（每人一行，可带 `subject_id` 表头） |

两份更正样例都可在 Swagger UI 的 `POST /sources` 里通过 “Try it out” 直接上传（`file` 选 CSV、`base_version` 填所依据的版本号）。

输出 CSV 保留原表头与原列序，仅把 `subject_id` 列的值换成研究代号。未同意（或已撤回）者的行不会出现；因此输出行数 = 发起时已同意且在**该批次固定版本明细**中出现的人数 × 其行数。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/sources/current` | 查询当前生效的源版本（版本号、摘要、行数、对象数等） |
| `GET` | `/sources` | 列出所有已启用版本（含当前版本标记 `is_current`） |
| `GET` | `/sources/{version}` | 查询单个已启用版本 |
| `POST` | `/sources` | **上传整份更正 CSV 换版**：表单字段 `file`（原格式 CSV）+ `base_version`（所依据版本）；成功返回 201 |
| `GET` | `/sources/{version}/download` | 下载任一已启用版本的原始 CSV（含已被取代的旧版，用于溯源） |
| `GET` | `/subjects` | 列出受试者同意状态与撤回序号 |
| `GET` | `/subjects/{subject_id}/consent` | 查询单人状态 |
| `PUT` | `/subjects/{subject_id}/consent` | 请求体 `{"consented": true/false}`；授予或撤回 |
| `POST` | `/batches` | 立即受理**此刻已同意**者并固定当前源版本，后台异步生成，返回 202 |
| `GET` | `/batches` | 批次列表（每条含 `source_version`） |
| `GET` | `/batches/{batch_id}` | 批次详情（含来源版本、事件时间线、失败原因） |
| `GET` | `/batches/{batch_id}/download` | 下载 CSV；校验摘要后才流式返回 |

换版接口状态码：

- `201` — 整份校验通过、保存成功且所依据版本仍是当前版，已启用；
- `400`（`source_invalid`）— 上传 CSV 整份校验失败（编码、表头缺列、字段数不齐、缺受试者号、无数据行等），**当前源不变**；
- `409`（`source_version_conflict`）— 所依据版本已不是当前版（并发换版或未基于最新版），**当前源不变**；需重新拉取当前版再改。

下载状态码（批次）：`200` 可下载；`404` 批次不存在；`409` 生成中/失败/文件缺失或被改动；`410` 因撤回被**永久**失效。

## 核心语义

### 源文件换版

- **整份校验、原子启用**：上传先在内存中对**整个文件**完成 UTF-8 解码、表头与逐行字段校验，全部通过后才写入数据卷临时文件、`fsync` 并原子改名为 `sources/v<N>.csv`，最后在同一事务里登记 `source_versions` 行。任一步失败都不会出现半启用版本，当前源保持不变。
- **乐观并发，同版只成功一次**：激活在进程锁 + `BEGIN IMMEDIATE` 事务内再次核对“当前版本 == `base_version`”。两个并发、依据同一版本的替换，只有一个能激活（201），另一个得到 409 且不改变当前源。
- **批次固定受理时版本、生成不混用**：每个批次在受理事务中把当时的当前版本号写入批次行；工作线程只读取该版本冻结的不可变文件。生成期间换版不会让批次混入新旧两套数据。批次详情与列表均注明 `source_version`，事件时间线也记录受理时版本。
- **换版不动既有数据**：换版不修改同意状态、研究代号注册表或任何旧批次文件；撤回规则与失效语义完全照旧。
- **历史可溯源**：已启用版本只增不改、不删除，旧版 CSV 与摘要长期保留并可下载；旧批次可凭 `source_version` 回溯到它所用的确切明细。
- **崩溃安全、更正不丢失**：源文件先落盘并 fsync，再提交版本登记。激活中途退出后重启，只可能使用**完整提交**的版本；未登记的孤儿文件与临时文件在启动时清理。一旦提交成功，更正已持久化，重启后仍然生效。
- **兼容旧数据卷**：对换版功能上线前的旧数据卷，首次启动自动把配置 `INPUT_CSV` 登记为初版 v1（拷贝进数据卷并计算摘要），并把历史批次行回填为 `source_version=1`；旧库通过 `ALTER TABLE` 平滑加列，迁移幂等。

### 同意与生成（沿用原有保证）

- **受理快照**：`POST /batches` 在事务内读取当时 `active=1` 的受试者并逐个登记入库、写入代号。之后新同意的人不加入本批；生成期间撤回的人使本批失效。
- **稳定代号**：代号由持久随机密钥的 HMAC-SHA256 映射所得（8 位、去掉易混字符），同一受试者跨批次、跨源版本恒定，且无法仅凭受试者号推导。代号只在受理事务中铸造。
- **撤回永久失效**：撤回会把该受试者登记过的**所有**批次（生成中或已完成）置为 `invalidated` 并物理删除 CSV；后续下载一律 410，重新同意也不恢复旧批。
- **生成中撤回**：工作线程每处理若干行重读状态；完成提交时在锁内再次校验，消除“撤回与完成”竞态。
- **失败不供数 / 重启恢复**：生成异常或摘要登记失败 → 批次 `failed` 且无可下载文件；下载前总是校验大小与 SHA-256。启动时把遗留 `running` 批次标 `failed`，校验所有 `completed` 文件，损坏者标失败，完好者仍可下载。
- **已在途下载可结束**：下载在状态校验通过后以已打开的文件句柄流式输出；期间撤回取消后续请求，但不中断已开始的响应。

## 数据卷布局

```
/data
├── deid.sqlite3          # 同意、代号、source_versions 版本登记、批次与事件
├── sources/
│   ├── v1.csv            # 初版（配置 CSV 的不可变拷贝）
│   ├── v2.csv            # 第一次更正
│   └── v3.csv ...        # 后续更正，只增不改
└── batches/
    └── <batch_id>.csv    # 各批次生成结果（含其固定版本的数据）
```

## 配置

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DATA_DIR` | `./data` | 持久化目录（容器内 `/data`），源版本与批次都在此 |
| `INPUT_CSV` | `samples/inputs/lims.csv` | 初始明细 CSV 路径（仅首次启动登记为 v1，之后以 API 换版为准） |
| `INITIAL_CONSENT_CSV` | `samples/inputs/initial_consent.csv` | 初始同意名单路径 |
| `ROW_DELAY_SECONDS` | `0` | 每行模拟延迟，仅用于演示生成中换版/撤回 |
| `CHECK_INTERVAL_ROWS` | `50` | 工作线程每隔多少行复查批次有效性 |
| `MAX_UPLOAD_BYTES` | `52428800`（50 MiB） | 源文件上传大小上限，超出返回 413 |

## 直接运行（不经 Docker）

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
DATA_DIR=./data uvicorn app.main:create_app --factory --port 8000

```
